# Known limitations

These limits describe what users can rely on and how to work around accepted boundaries.
Decision references explain the scope. Resolved safeguards retain their identifiers so older
links still work; a resolved row does not describe an outstanding defect.

## Limits and safeguards

| ID | User impact | Decision / source | Current behavior | Scope | Workaround |
| --- | --- | --- | --- | --- | --- |
| B-01 | Extremely small budgets can cut a closing fence in the low-level cap-first snippet formatter. | D-28; `src/retrieval.ts` | The hard output cap takes precedence in that formatter. | Accepted behavior | Increase the response budget; a formatting fence is not an input security boundary. |
| B-02 | A symlink to a regular project config is followed. | D-15; `src/config.ts` | Tom chose to keep this for linked monorepos and dotfiles. | Accepted behavior | Treat project write access as config-authoring access; review cloned configs. |
| B-03 | A configured shared cache is not refused merely for its owner or mode. | D-84; `ensureCacheRoot` in `src/cache.ts`; README cache section | Shared roots remain allowed; symlinks and unsafe file types have separate checks. | Accepted behavior | Choose a private cache directory and restrict who can write its parents. |
| B-04 | Cache migration and followed-page cleanup retain synchronous check-then-act windows. | D-83/D-85; `src/cache.ts` | Descriptor-pinned reads and canonical-root checks close broader escapes; Tom accepted the remaining migration/cleanup boundary. D-95 separately covers the configured-root race. | Accepted behavior | Restrict writes to cache ancestors; these operations are not a fully atomic filesystem boundary. |
| B-05 | Cache-read leaf symlinks could previously expose an unrelated local file. | D-83; `readCache` in `src/cache.ts` | Regular-file and descriptor-identity checks refuse the demonstrated swapped leaf. | Resolved safeguard | Keep the cache private; see B-04 and B-06 for the remaining path races. |
| B-06 | A process that can replace cache ancestors can still race a later operation. | D-95; `src/cache.ts`; `9fc62f6` | Configured-root ancestor swaps are refused after canonical-root pinning. D-95 retains a configured-root check-then-use race; migration and followed-page cleanup are covered separately by B-04/B-25. | Accepted behavior | Restrict who can write parent directories; this is not descriptor-relative containment. |
| B-07 | Eviction refuses a symlinked cache root or child. | D-46; `src/cache-evict.ts` | The refused path is not swept or followed. | Resolved safeguard | Use a real cache directory; do not rely on eviction to repair a linked path. |
| B-08 | Test predicates for multi-line output intentionally differ from the production text filter. | `src/text.ts`; PAR-926 | Production control ranges have a source-derived tripwire; rendered multi-line tests allow newline separators. | Accepted behavior | Use the shared production cleaner for new output surfaces. |
| B-09 | A forged library identity cannot earn a refreshed cache timestamp. | `touchCache` in `src/cache.ts` | `touchCache` calls `metaMatchesLibrary` and leaves a mismatched record unchanged. | Resolved safeguard | Remove invalid metadata and refetch instead of editing its library identity. |
| B-10 | Persisted timestamp checks share one validator. | `src/cache-meta.ts`; `test/par1044-l33-shared-helpers.test.ts` | Activity, project, search-index and doctor stores import the one exported `validIsoInstant` (shape, then a real date); the name bound and BOM handling also have one copy each. | Resolved safeguard | Use the shared validator when extending persistence. |
| B-11 | DNS preflight does not pin the address used by the connection. | D-89b; `src/address-policy.ts` | Default lookup failure proceeds; strict DNS refuses failure, timeout or empty answers. A second lookup can still rebind. Strict DNS is not persisted with resolved-package records. | Accepted behavior | Keep `VIBECTX_STRICT_DNS=1` or user-config `strictDns` enabled across restarts; use network egress controls for connection-level isolation. |
| B-12 | DNS lookup can occupy the runtime thread pool below fetch concurrency. | D-89c; `src/address-policy.ts` | DNS pressure can reduce throughput even while fetch slots are free. | Current limit | Reduce simultaneous work or use a local caching resolver. |
| B-13 | Following links has a shared deadline and can return a partial answer. | D-89c; `src/get-docs.ts` | The link-following phase has an aggregate deadline and cancellation. | Resolved safeguard | Retry or narrow the topic when the answer reports partial results. |
| B-14 | A full refresh has a deadline per library rather than one overall deadline. | D-89c; `src/refresh.ts` | Tom accepted approximately 1,800 seconds for 30 libraries rather than a half-updated cache. | Accepted behavior | Refresh one library at a time when latency matters. |
| B-15 | A primary-candidate switch followed by a 304 can retain older followed-page attribution. | D-90c | A 304 does not invalidate followed-page content. | Accepted behavior | Refresh the library; immediate repair after a 304 is not guaranteed, while a changed 200 refresh clears stale followed pages. |
| B-16 | One URL can share a cache entry across response representations. | D-90j | The cache key has no `Accept` discriminator. Tom's separate-project decision places representation-aware keys in VibeCTX 2.0, deferred-by-decision. | Deferred behavior | Avoid a configured endpoint whose response varies by request role or headers. |
| B-17 | Repeated versioned retrieval can repeat package resolution and consume its quota. | D-90j | Memoization was deferred-by-decision in VibeCTX 0.2.1 to preserve resolution freshness. | Deferred behavior | Prefer already-cached offline reads or avoid repeated identical online pin lookups. |
| B-18 | Epoch-pinned Python versions cannot be checked as ordinary version pins. | D-90i; `src/project-deps.ts` | Dependency discovery keeps the package and reports the unsupported pin. | Resolved safeguard | Inspect the pin note; do not assume the retrieved document proves an epoch version. |
| B-19 | A healthy doctor result does not grade answer quality. | D-91; `src/doctor.ts` | Index-only and missing-body results are disclosed, but shallow relevant prose can still be healthy. | Accepted behavior | Inspect the source and actual answer; use another topic or a fuller configured source. |
| B-20 | Some built-ins use shallow or single-page content. | D-91; D-101 (registry candidates); D-107 (doctor probes and first sources); `src/registry.ts` | Tailwind and TanStack Query now start from one checked docs page each (responsive design; queries), not a full documentation corpus; README fallbacks remain later candidates. External endpoints can still disappear. | Current limit | Configure a fuller public text endpoint and use doctor to check it. |
| B-21 | Cross-library search indexes primary documents only. | D-91; `src/search.ts` | `get_docs` can also retrieve followed pages, so the two tools have different coverage. | Accepted behavior | Use `get_docs` with a topic for linked content. |
| B-22 | The retrieval evaluation ranks primary documents without following links. | D-91; `scripts/eval-retrieval.mjs` | Its score measures that corpus and those labels, not all linked documentation. | Accepted behavior | Evaluate link-following separately before making broader quality claims. |
| B-23 | Authenticated docs and custom request headers are unsupported. | D-90j; `src/retrieval.ts` | Tom chose public docs only for this release. | Accepted behavior | Use public endpoints; do not put credentials in documentation URLs. |
| B-24 | Two processes could lose a completed activity-log entry while rotating the same live file. | D-104; `src/activity-log.ts`; `test/activity-log-rotation-race.test.ts` | Rotation at 4,000 entries keeps a linked trail and five archives by default. Rotation is single-holder via an exclusive marker; the demonstrated same-file interleaving retains the completed peer entry. Crashed-holder and aged markers recover. | Resolved safeguard with platform and handoff limits | Appends remain lock-free; late appends stay in the archive and are reported by `log --trail`. The no-hard-link fallback retains the separate race in Log rotation; native Windows and every multi-process marker-handoff schedule are unverified. |
| B-25 | Cache migration and followed-page cleanup retain synchronous check-then-act windows. | D-83/D-85; `src/cache.ts` | Tom accepted the remaining migration/cleanup boundary; D-95 separately covers the configured-root race. | Accepted behavior | Restrict parent-directory writes: this is the migration/cleanup boundary, not broad cache-root exposure. |
| B-26 | JSON error text cannot forge a reported parser position. | `src/activity-log.ts`; `src/search-index.ts` | Only an end-anchored parser position is displayed. | Resolved safeguard | Remove or regenerate a corrupt store rather than treating its quoted text as a diagnostic. |
| B-27 | npm releases before 0.3.0 (`@blackraptorai/vibectx` 0.1.2 and `@blackraptorai/docs-cache-mcp`) predate security fixes. The 0.3.0 tarball bundles its runtime dependencies exactly as their authors published them, including those packages' own test files. | Decisions 23 and 24; README install warning and Development | 0.3.0 is published to npm; the maintainer retires the older packages after that publish (unpublish where npm policy allows, otherwise deprecate with a pointer to the Labs repository). Bundling keeps the exact audited tree and carries the `ip-address`/`fast-uri` security overrides that npm ignores for consumers; VibeCTX's own packed files contain no tests. | Accepted risk until retired; bundled upstream test files accepted | Install 0.3.0 or later, from npm or source. |
| B-28 | Older retrieval-quality claims do not establish current coverage. | D-91 | Evaluation labels and corpus were reconciled; historical results retain their measured scope. | Resolved safeguard | Read the corpus and provenance before comparing scores. |
| B-29 | Markdown retries do not recurse through query or fragment links. | D-91; `src/fetcher.ts` | Explicit retry state bounds the retry to one additional attempt. | Resolved safeguard | Inspect fetch diagnostics when both attempts fail. |
| B-30 | Tailwind fallback coverage is an upstream-content issue, not an ASCII-only tokenizer limit. | D-91; B-20 | Unicode search is shipped; fuller upstream content remains a separate concern. | Resolved safeguard | Configure a better source instead of changing tokenization to compensate for missing prose. |
| B-31 | Unknown-library diagnostics bound and clean registry names. | `unknownLibraryMessage` in `src/registry.ts` | The Known list does not echo unbounded raw keys. | Resolved safeguard | Use a listed library name or add a valid configured entry. |
| B-32 | Search renders fetched headings and prose inside a data fence. | D-30; D-48; `src/search.ts` | Retrieved text is separated from tool instructions. | Resolved safeguard | Treat the fenced documentation as source data, not commands. |
| B-33 | Shared text cleaning removes Unicode Tags and control characters. | `src/text.ts` | The filter covers U+E0000–E007F and its source-derived checks. | Resolved safeguard | Use the shared cleaner for new rendered fields. |
| B-34 | Activity reads and schema probes are size-bounded. | `src/activity-log.ts` | Oversized stores are not parsed without a bound; rotation archives oversized live logs. | Resolved safeguard | Use log retention or disable logging to control disk use. |
| B-35 | Text clipping preserves complete surrogate pairs. | `clipText` in `src/text.ts` | An astral character is not split into a lone surrogate. | Resolved safeguard | Keep using the shared clipping helper for bounded text. |
| B-36 | Echoed retrieval identifiers use variable-width data fences. | `src/retrieval.ts`; `src/get-docs.ts` | Tom chose to extend the existing fetched-data fence. This is a text-format boundary, not a universal prompt-injection guarantee. | Resolved safeguard | Keep treating retrieved prose as untrusted; registry descriptions have separate behavior. |
| B-37 | Cache-root refusal is visible through the appropriate output channel. | `src/doctor.ts`; README cache section | Tom chose channel-split reporting: terminal detail, redacted model output and default JSON. | Resolved safeguard | Run doctor locally; opt into a full path only when needed. |
| B-38 | SHA-pinned workflow actions need continuing updates. | `.github/dependabot.yml` | Weekly action updates are configured; configuration alone does not prove bot PRs have run or merged. | Current limit | Review and merge the action update PRs before a release; alert settings need administrator verification. |
| D-96 | URL paths can contain secrets that are not redacted. | D-96 | Userinfo, query and fragment are redacted; document paths remain identities. Opt-in debug stderr can show raw URLs. | Accepted behavior | Never use token-bearing paths; keep debug output private. |
| D-97 | Disclosure can proceed online without an explicit Allow answer. | D-97; D-103 (consent update check) | Cancel, timeout or an unavailable prompt is remembered as disclosed. Connecting makes no request; update checks require allowed consent. | Accepted behavior | Use `vibectx consent deny` for cache-only MCP tools or reset before changing the answer. |
| D-98 | Inbound stdio frames have no VibeCTX transport size cap. | D-98 | The launching client buffers frames before application schema bounds run. | Accepted behavior | Use a trusted client that bounds request sizes. |
| Project config | A committed project config can opt a library into internal hosts. | D-89a; `src/config.ts` | `allowInternalHosts` is authorable by a project writer. Curated primary URLs may name internal hosts; redirect hops and followed links still obey the textual host policy. | Accepted behavior | Review configs in cloned repositories and control project write access. |
| Concurrent warm | Two concurrent warms under a small cap can both report cached. | `src/warm.ts`; `src/cache-evict.ts` | Another writer or later eviction can remove content after either report; there is no shared cache lock. | Current limit | Recheck offline retrieval or warm again with a larger cap. |
| Log rotation | Retained logs keep query text on disk, and hashes are not an attestation. | D-104; `src/activity-log.ts` | About 24,000 queries fit in the default live-plus-five-archive trail. At sequence 999,999,999,999 the writer stops rotating and keeps appending, with a warning rather than an unreadable link. A filesystem without hard links uses a check-then-rename fallback that can overwrite a concurrently created target. | Accepted behavior | Set `VIBECTX_LOG_ARCHIVES` or user-config `logArchives`, use zero archives to reduce retention, or `VIBECTX_NO_LOG=1` to stop logging; protect the cache from other writers. |
| Update check | Reset or deny does not cancel an already-started allowed update check. | D-103 (consent update check); `src/server.ts` | At most that in-flight GET and notice can finish. A project false silently overrides a user opt-in. | Accepted behavior | Reset before the first online call; inspect config precedence when an opted-in check is absent. |
| CLI consent | An explicit online CLI command records a disclosure when no answer exists. | D-97; D-103 (consent update check); `src/cli.ts` | The MCP host then uses that stored answer rather than prompting again. | Accepted behavior | Run `vibectx consent reset` before reconnecting to ask again. |
| Partial eviction | A filesystem error can prevent eviction from meeting the cache cap. | `src/cache-evict.ts`; `test/par1045-quality.test.ts` | The sweep reports failure counts and error codes, and recounts real files after a partial deletion and subsequent peer-deleted queued candidates instead of subtracting stale sizes. | Resolved accounting safeguard; deletion may still fail | Correct permissions or storage errors and retry; inspect stillOverCap when protected or undeletable files retain excess bytes. |
| Autowarm | Background warming fetches only the project's matching dependencies by default; a repository can name a committed config library among them. | D-105; `src/autowarm.ts`; `src/server.ts` | Unknown dependencies resolve only under allowed consent, taking at most 20 of the shared 100 hourly lookups per process; no user capacity is reserved. A later deny or reset stops subsequent lookups; one already in flight may finish. Full configured warming is opt-in. | Accepted project-config boundary and per-process budget | Review committed config in cloned projects; use `VIBECTX_NO_AUTOWARM=1` to disable background work or `VIBECTX_AUTOWARM=all` to choose full warming. |
| Activity append | A Windows last-moment symlink swap can create an empty outside file; a same-user hard link can redirect an append and mode change. A directory at activity.json produces EISDIR and no record. | `src/atomic-store.ts`; `src/activity-log.ts` | POSIX O_NOFOLLOW and descriptor checks refuse symlinks and non-regular files. The Windows fallback checks identity after open, before writing; O_CREAT may already have created an empty target. A hard link remains a regular file. Windows file-ID reliability is unverified. | Platform fallback and same-user cache writers | Keep the cache private, avoid same-user untrusted writers, and inspect an unexpected activity.json directory before moving it aside. |
| Temporary-file sweep | An old temp-shaped user file placed inside the cache can be removed at startup. | `src/atomic-store.ts` | The sweep checks regular-file type, an exact PID/timestamp .tmp name and age of at least one minute. It does not know who created a matching file. | Files matching the temp-name contract | Keep unrelated files outside the cache; symlinks, directories and recent or future-stamped names are not swept. |
| Legacy cache integrity | A legacy truncated document can still be served as fresh because it has no stored content hash. | `src/cache.ts`; `test/par1042-answer-honesty.test.ts` | New writes verify SHA-256 body integrity; 304 revalidation leaves the entry hashless and does not reconstruct its original body. | Compatibility with older cache entries | Remove the affected cached document and fetch it again to obtain a hashed write; hash checks do not authenticate a same-user cache writer. |

## Supported scope

Deferred-by-decision work is outside the current release behavior, rather than an unanswered
release choice. The representation-aware cache key is VibeCTX 2.0 work; version-resolution
memoization retains its VibeCTX 0.2.1 deferral. Tom's separate-project direction remains unchanged.
Historical full-suite evidence was macOS-only until `8898a76`; that evidence does not certify
Windows behavior.

## Compatibility choices

These eight behaviors were decided by Tom, 2026-09-21. They are compatibility choices for users,
not pending approvals.

| ID | Compatibility choice | How to use it |
| --- | --- | --- |
| B-02 | Follow symlinked regular project config. | Review linked monorepo and dotfile configs. |
| B-04/B-25 | Retain the migration/cleanup boundary separately from D-95's configured-root race. | Restrict cache-ancestor writes. |
| B-13 | Bound link following with one aggregate deadline. | Retry a disclosed partial result or narrow the topic. |
| B-14 | Keep per-library refresh deadlines. | Refresh individual libraries when an overall wait is too long. |
| B-23 | Fetch public docs only. | Do not configure authenticated endpoints. |
| B-24 | Append one line per activity entry without a lock. | Inspect the linked trail for concurrent late appends. |
| B-36 | Fence echoed retrieval identifiers with the existing data format. | Treat the fenced content as untrusted source text. |
| B-37 | Split refused-root reporting by output channel. | Use local doctor output for terminal detail. |
